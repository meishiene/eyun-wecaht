# 功能归属与交接

更新于 2026-11-04。接手的人先看这份：每个功能属于哪个机器人、做到什么程度、哪些没做、要向谁拿什么。

## 1. 整体结构

```
微信私聊 ──> AstrBot ──> kb_digest 插件 ──┐
                                          ├──> 知识库（git 目录）<── kb_web 只读网页
                     seed/ 导入、补全脚本 ─┘          ^               kb_backup 每日备份
                                                      └── 人工用 /审 等指令维护

微信群+私聊 ──> Eyun 控制台 ──回调──> eyun_recv ──> SQLite ──> response_stats
                                  （与知识库没有任何连接，未上线）
```

要点：**Eyun 那一半不写知识库，AstrBot 那一半不收群消息。** 两边目前没有数据往来。

## 2. 功能归属表

### A. 属于 AstrBot（已上线）

| 功能 | 怎么用 | 代码位置 |
|---|---|---|
| 收集私聊里的文字和图片，不回复；缓冲区落盘，重启不丢 | 直接粘贴 / 发图 | `astrbot/plugins/kb_digest/main.py` `collect` |
| 把一批消息整理成一个待入库问题（分类、简要、报告、标签、原理说明、归属侧、类型、相关分类） | `/整理 [标题]` | `main.py` `digest` |
| 图片识别（转成文字后一起整理） | 自动 | `main.py` `_describe` |
| 查重与合并（大模型判断是否同一问题） | 自动 + `/合并 A B` | `main.py` `digest` `_merge_into` |
| 入库并记 git | `/入库` | `main.py` `commit` |
| 检索、查看详情（发回报告文件） | `/查`、`/看`、`/树`、`/待入库`、`/条数` | `main.py` |
| 维护 | `/改类`、`/状态`、`/同意新类`、`/清空` | `main.py` |
| 标签体系（词表、别名、待确认新标签、三层视图） | `/标签 [类\|树]`、`/同意新标签`、`/加别名` | `main.py` + `kb_core.py` |
| 人工审核（1~5 分，校正说明存为基准回答，AI 原稿保留） | `/审 编号 分数 [说明]`、`/待审` | `main.py` + `kb_core.py` |
| 白话入口（以 `@11` 开头；会改库的先复述、回「是」才执行） | `@11 帮我整理刚发的` | `main.py` `talk` + `nl_intent.py` |

### B. 属于 Eyun（代码完成，未上线，已放弃）

| 功能 | 说明 | 代码位置 |
|---|---|---|
| 回调接收（群：文本/图片/引用；私聊：文本/图片/引用/文件） | 验路径密钥 → 去重落 SQLite → 立刻回 200 | `eyun/eyun_recv.py` |
| 首次响应时长统计 | 平均/中位/P90/最长、按员工拆分、工作时间口径、超时未回复清单；只统计群 | `eyun/response_stats.py` |
| 部署文件 | 加固的 systemd 服务 | `eyun/eyun-recv.service` |

**Eyun 这一半没有的东西：** 发送消息、下载图片和文件、调用大模型、解析指令、写知识库。

### C. 与机器人无关（换哪个机器人都在用）

| 功能 | 位置 |
|---|---|
| 知识库核心：分类树、存取、检索、脱敏、标签、审核、相关分类（不依赖 AstrBot） | `astrbot/plugins/kb_digest/kb_core.py` |
| 白话指令的解析与校验（不依赖 AstrBot） | `astrbot/plugins/kb_digest/nl_intent.py` |
| 只读网页：分类、问题详情（含归属侧/类型/审核/相关分类）、搜索、标签层级、排查手册、备份状态条 | `astrbot/web/kb_web.py` |
| 每日备份（打包、校验、轮换、写状态） | `astrbot/backup/` |
| 种子导入（解析 → 大模型归类 → 去重 → 生成）、标签重整、**存量补全** | `astrbot/seed/` |

### D. 会议纪要（2026-11-03）里要求、但两边都没做的

| 纪要里的要求 | 现状 |
|---|---|
| 群消息定时/自动采集并全量留存 | AstrBot 插件只订阅私聊事件；Eyun 能收群消息，但**没有人把它转成知识库条目** |
| 群消息自动归类 → AI 建议回答 → 人工打分 → 校正成基准回答 | 后半段（打分、基准回答）在 `/审` 里有了；前半段（从群消息自动归类）没有 |
| 后台群列表、群与客户/供应商绑定 | 没有 |
| 转发聊天记录自动关联客户后台数据 | 没有，仓库里没有任何后台数据接口 |
| 客户用量异动提醒（按周） | 没有，缺后台用量数据 |
| 补货客户清单与批量推送 | 没有，依赖 SCRM |
| 对客户群消息采集做数据安全风险评估 | 没有 |
| 苏岩的待办：拿真实 query 问 AI，看回复效果 | 没有，不需要写代码 |

## 3. AstrBot 现状与注意事项

- 线上有 **110 条**已入库问题，**全部**带「AI 补全待审」标记（2026-11-04 补全）。用 `/待审` 看，用 `/审 编号 分数` 确认。
- **`/审`、`/待审` 暂不支持白话入口**（`@11`），只能用斜杠指令。
- 命令后必须有空格：`/查 401`，不是 `/查401`。
- 插件只处理私聊；收到文件只记日志，不处理。
- 备份和现场在同一块硬盘上，防不了硬盘损坏（见 `astrbot/README.md`）。
- 补全脚本需要模型 Key；服务器直连模型接口不通时，用环境变量 `SEED_PROXY` 走代理。
- `astrbot/README.md` 里的服务器路径、服务名、备份还原步骤都是线上实际在用的。

## 4. Eyun 遗留事项

2026-11-03 评估后决定不用：非官方协议有封号风险；小号当天就因「重连失败」掉线，掉线期间消息收不到。

已撤掉：Eyun 控制台的回调设置、隧道入口、`eyun-recv` 服务。

**还没清理，需要人工处理：**
- 服务器上还留着 Eyun 目录和数据目录，里面有测试期间的**群消息和私聊原始数据**。不用的话建议删除。
- Cloudflare 里给回调用过的 CNAME 记录需要到 Cloudflare 控制台手动删。
- Eyun 控制台里的实例和账号，按需处理。

## 5. 交接清单（仓库里没有，要单独拿）

| 要什么 | 在哪 / 向谁 |
|---|---|
| 服务器登录方式 | 负责人。**不要写进仓库或聊天记录；之前的 root 密码出现在过对话里，建议更换** |
| 知识库数据（`data/kb`，含 git 历史） | 只在服务器上；备份在服务器备份目录 |
| 种子案例文档及派生文件（`source.md`、`cases.json`、`draft_raw.json` 等） | 负责人。没有它们，`build.py`、`classify.py` 跑不起来 |
| 模型 Key | AstrBot 的模型提供商配置里 |
| 网页访问密码 | 服务器上 `kb-web` 的环境变量文件（仅 root 可读） |
| 代理节点配置 | 服务器上 `astrbot-mihomo` |
| Eyun 控制台账号、Cloudflare 账号 | 负责人 |

## 6. 改了代码以后怎么部署（AstrBot 部分）

1. 在 `astrbot/` 目录跑全部测试，确认通过。
2. 在服务器上先手动备份：`systemctl start kb-backup.service`，看 `journalctl -u kb-backup.service -n 5` 显示成功。
3. 把旧版插件和网页文件拷一份留底，再替换：插件 `kb_core.py`、`main.py`、`nl_intent.py` 放进 AstrBot 数据目录下的 `plugins/kb_digest`；网页 `kb_web.py` 放进 `web` 目录。
4. 重启：`docker restart astrbot`、`systemctl restart kb-web`，看 `docker logs astrbot` 里 `kb_digest` 加载无报错。
5. 改了知识库内容的操作（如补全）会自动 git 提交；回滚用 `git revert`，或按 `astrbot/README.md` 的备份还原。
